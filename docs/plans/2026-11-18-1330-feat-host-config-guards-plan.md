# Защита от неверной настройки хоста - Plan

## Goal Capsule

- **Objective:** хост с пустым или неверным макросом шаблона «Web service by itforprof.com» показывает ошибку настройки, а не проверяет молча чужой адрес и не замолкает.
- **Means:** сверка `{$WEB_SERVICE.HOST}` с хостом из URL, триггер «нет данных» на https-проверке TCP и исправленные описания макросов (KTD1–KTD3).
- **Product authority:** владелец репозитория. Выкладка на серверы только после его «да».
- **Open blockers:** нет.
- **Execution profile:** правка YAML шаблона, словаря, тестов и документации в ветке; выкладка (U4) отдельным шагом.
- **Stop conditions:** остановиться и спросить, если пробное сравнение показывает удаление или смену uuid, если после импорта новая сверка или триггер «нет данных» открылись на хосте, где их не ждали (Success Criteria), или если хоть один TCP-элемент стал NOTSUPPORTED.
- **Who finishes:** исполнитель доводит U1–U3 до зелёных локальных проверок и коммита в ветке (GitHub Actions выключены). U4 выполняется после «да» владельца.

## Product Contract

### Summary

Шаблон получает два новых сигнала. WARNING «Макрос имени хоста не совпадает с URL» срабатывает, когда `{$WEB_SERVICE.HOST}` пуст, с опечаткой, с пробелом или остался от другого сайта; пока он открыт, ложная TCP-авария подавлена. AVERAGE «Нет данных TCP-проверки» срабатывает, когда https-проверка TCP перестала получать значения, например из-за нечислового порта или отсутствия адреса. Описания макросов и README говорят, что обязательно задать на новом хосте.

### Problem Frame

Шаблон доверяет макросам хоста и не замечает их ошибок. Проверено 18.11 на временных хостах и обходом всех хостов шаблона на двух серверах.

- Пустой `{$WEB_SERVICE.HOST}` при интерфейсе `127.0.0.1` отправляет TCP-проверку на сам сервер мониторинга. На втором сервере так три хоста месяцами проверяли не те машины; ошибку нашли только при выкладке 2.6.0.
- Пустой `{$WEB_SERVICE.HOST}` без интерфейса делает TCP-элемент NOTSUPPORTED («Check service item must have IP parameter or host interface specified»). TCP-триггеры и условие TCP в триггере сертификата становятся UNKNOWN, и хост замолкает.
- Пробел в начале `{$WEB_SERVICE.HOST}` даёт TCP-значение 0 и ложный AVERAGE «Нет соединения TCP».
- Нечисловой `{$WEB_SERVICE.HTTPS.PORT}` или порт с пробелом («443 ») делает TCP-элемент NOTSUPPORTED («Invalid third parameter»). Сверка порта из 2.6.0 при этом срабатывает, но TCP-триггеры и условие в триггере сертификата молчат.
- Описание макроса `{$WEB_SERVICE.HOST}` в шаблоне утверждает, что по умолчанию берётся хост из URL. Значения по умолчанию нет.

Сейчас на production все 49 хостов настроены верно, на втором сервере у двух хостов `{$WEB_SERVICE.HOST}` пуст, но интерфейс указан по имени сайта. Хоста, которому нужно намеренно другое имя в `{$WEB_SERVICE.HOST}`, чем в URL, нет ни на одном сервере.

### Requirements

**Сверка имени хоста**

- R1. Шаблон сообщает с важностью WARNING, когда хост, который `web_check.py cert` взял из `{$WEB_SERVICE.URL}` (поле `host` его JSON), не равен `{$WEB_SERVICE.HOST}`. Это покрывает пустой макрос, опечатку, пробелы и макрос, оставшийся от другого сайта.
- R2. Пока свежая проверка сертификата показывает расхождение имени хоста или порта, «Нет соединения TCP {$WEB_SERVICE.HTTPS.PORT}» молчит, а уже открытый закрывается: проверка смотрит не на тот адрес, и её AVERAGE ложный.

**Нет данных TCP-проверки**

- R3. Шаблон сообщает с важностью AVERAGE, когда https-проверка TCP не получает значений 15 минут (три интервала опроса по умолчанию): элемент NOTSUPPORTED, адрес не задан или порт нечисловой. Пока у веб-сценария тоже нет данных, сигнал молчит: молчит весь сборщик, и задача по этой причине уже есть.

**Описания и инструкция**

- R4. Описание `{$WEB_SERVICE.HOST}` говорит, что значение обязательно и равно хосту из `{$WEB_SERVICE.URL}` в нижнем регистре, а без него TCP-проверки идут на интерфейс хоста. Для кириллических доменов оба макроса, `{$WEB_SERVICE.URL}` и `{$WEB_SERVICE.HOST}`, пишутся в форме `xn--`: так `{$WEB_SERVICE.HOST}` заполняется с 2.1.1, и на A-label выписаны сертификаты. Описания макросов портов говорят, что значение — только цифры, без пробелов. Описание `{$WEB_SERVICE.DIAG.CHECK.INTERVAL}` говорит, что при интервале 15m и больше «Нет данных TCP-проверки» (R3) срабатывает постоянно, а при интервале от 5m до 15m — после одного пропущенного опроса.
- R5. README шаблона содержит перечень шагов при добавлении хоста: `{$WEB_SERVICE.URL}`, `{$WEB_SERVICE.HOST}`, `{$WEB_SERVICE.HTTPS.PORT}` для нестандартного https-порта, запуск `scripts/sync-domain-registry-owners.py` после добавления или повторного включения хоста.

**Сборка, версия, выкладка**

- R6. Русская версия собирается из словаря; профиль Certificate-TLS не получает новых объектов (в нём нет TCP-проверок).
- R7. Версия полного шаблона `7.0-2.7.0` везде, где сейчас записана `7.0-2.6.0`, запись в `CHANGELOG.md`.
- R8. Выкладка по принятому в проекте порядку (2.6.0, U5). Перед импортом на хостах, где сверка сработала бы сразу, `{$WEB_SERVICE.HOST}` выставлен после проверки доступности, чтобы выкладка не открыла ни одного нового сигнала.

### Key Decisions

- **Сверка по полю `host` проверки сертификата, а не по разбору URL в Zabbix.** Простой проверкой Zabbix URL не разобрать, а `check_cert` уже кладёт в JSON хост из URL в нижнем регистре, до сетевого обращения. Тот же приём, что у сверки порта в 2.6.0. Governs R1.
- **Без исключения для намеренно другого имени.** Ни на одном хосте `{$WEB_SERVICE.HOST}` намеренно не отличается от хоста URL. Исключение (макрос с контекстом или флаг) добавляется позже одной строкой, если такой хост появится. Governs R1.
- **AVERAGE для «нет данных», как у остальных триггеров нет-данных шаблона.** Проверка, которая молчит, — поломка мониторинга, ей нужна задача. Governs R3.
- **При сбое сборщика задача одна.** «Нет данных TCP-проверки» молчит, пока нет данных и у веб-сценария: интервал веб-сценария тоже задан макросом, поэтому при остановке прокси и при сбое кэша после перебалансировки молчат обе проверки. Ошибка настройки на одном хосте веб-сценарий не трогает, и TCP-сигнал срабатывает. Governs R3. (session-settled: user-directed — chosen over важность WARNING или AVERAGE без подавления: WARNING не даёт задачи при ошибке настройки, без подавления при сбое сборщика приходит лишняя задача; механизм — условие в выражении, а не зависимость, тоже user-directed: зависимость замораживала бы триггер, а NOTSUPPORTED-элемент не даёт значения, которое её снимает)

### Acceptance Examples

- AE1. **Covers R1, R2.** **Given** новый хост, `{$WEB_SERVICE.URL}` = `https://example.org/`, `{$WEB_SERVICE.HOST}` не задан, интерфейс `127.0.0.1`. **When** проходит первая успешная проверка сертификата. **Then** открыт WARNING о несовпадении `example.org` с пустым макросом; TCP-авария, если на localhost нет 443, подавлена. Если AVERAGE успел открыться до первой успешной проверки сертификата, он закрывается, как только проверка покажет расхождение.
- AE2. **Covers R1, R2.** **Given** `{$WEB_SERVICE.HOST}` = `" example.org"` (с пробелом). **When** TCP-проверка вернула 0 два раза подряд. **Then** открыт только WARNING сверки, без ложного AVERAGE.
- AE3. **Covers R3.** **Given** `{$WEB_SERVICE.HTTPS.PORT}` = `443 ` (с пробелом). **When** TCP-элемент NOTSUPPORTED 15 минут. **Then** открыт AVERAGE «Нет данных TCP-проверки»; сверка порта из 2.6.0 тоже открыта.
- AE4. **Covers R3.** **Given** `{$WEB_SERVICE.HOST}` пуст, интерфейса нет. **When** TCP-элемент NOTSUPPORTED 15 минут. **Then** открыт AVERAGE «Нет данных TCP-проверки», а при первой успешной проверке сертификата — и WARNING сверки имени.
- AE5. **Covers R1.** **Given** `{$WEB_SERVICE.HOST}` = `example.org`, URL `http://example.org/`. **When** проходит проверка сертификата (на 443). **Then** несовпадения нет.

### Success Criteria

- После выкладки сверка имени хоста и «Нет данных TCP-проверки» не открыты ни на одном хосте обоих серверов.
- Живая проверка до импорта подтверждает AE1–AE3 на временном хосте с триггерами INFO.

### Scope Boundaries

Рассмотрено и не делается:

- Отдельный сигнал для пустого `{$WEB_SERVICE.URL}`. Пустой URL уже даёт HIGH «Сбой веб-сервиса» (веб-сценарий: «<url> malformed») и INFO по ошибкам `web_check.py`; ошибка видна сразу. Изменит решение: случай, когда пустой URL прошёл незамеченным.
- Сверка и «нет данных» для http-проверки TCP. У неё нет триггеров, её NOTSUPPORTED ничего не скрывает. Изменит решение: появление триггера на http-проверке.
- Сигнал до первой успешной проверки сертификата. Обе сверки (порт и имя) берут значение только из успешных проверок; хост без единой успешной проверки сверяется после первой. «Нет данных TCP-проверки» закрывает часть этого случая, когда TCP-элемент NOTSUPPORTED. Изменит решение: реальный хост, где это скрыло ошибку.
- Автоматическая дедупликация WHOIS при добавлении хоста. Остаётся шагом процесса (R5). Сейчас два отключённых хоста production без макросов дедупликации; при их включении нужен запуск скрипта.
- Отдельный макрос периода для «Нет данных TCP-проверки». Порог 15m рассчитан на интервал 5m: он пропускает два опроса подряд. При интервале 15m и больше триггер срабатывает постоянно, от 5m до 15m — после одного пропуска; это записано в описании макроса интервала (R4). Так же устроен триггер нет-данных сертификата. Сейчас интервал нигде не переопределён. Изменит решение: хост, которому нужен интервал больше 5m.
- Точка в конце имени в URL (`https://example.org./`) даёт ложную сверку имени: `check_cert` её не убирает. Таких URL нет; исправление в `web_check.py` требует выкладки на все сборщики. Изменит решение: первый такой URL.
- Интервал `{$WEB_SERVICE.CERT.CHECK.INTERVAL}` больше 15m закрывал бы сверки между проверками из-за условия свежести (KTD2). Сейчас интервал нигде не переопределён. Изменит решение: хост с таким интервалом.
- Регистр в `{$WEB_SERVICE.HOST}`. Сравнение строк в Zabbix чувствительно к регистру, поэтому `Example.org` откроет сверку, хотя проверка работает. Описание макроса просит нижний регистр (R4); все текущие значения в нижнем регистре.

## Planning Contract

### Key Technical Decisions

- KTD1. **Элемент имени устроен как `web_check.cert.port`: зависимый от основного элемента сертификата, `NOT_MATCHES_REGEX "ok":false` с `DISCARD_VALUE`, JSONPath `$.host`, история 7d.** Значение строковое (CHAR), трендов у CHAR нет. Без `DISCARD_UNCHANGED_HEARTBEAT`: Zabbix пересчитывает триггер только по новому значению, а смена макроса без нового значения не пересчитывается (проверено при выкладке 2.6.0).
- KTD2. **Выражение сверки — строковое сравнение `last(.../web_check.cert.host)<>"{$WEB_SERVICE.HOST}"` и условие свежести `nodata(.../web_check.cert.host,15m)=0`, без зависимостей.** Проверено 18.11 на временном хосте: сравнение срабатывает и для пустого макроса, и для макроса с пробелом. Условие свежести закрывает сверку после 15 минут без успешной проверки сертификата: иначе сверка, открытая до аварии https-порта, держала бы подавленной настоящую TCP-аварию. Оно же ставит триггер на таймер `nodata()`, и исправленный макрос виден через 30 с. Так же меняется сверка порта из 2.6.0. (session-settled: user-directed — chosen over сверки без условия свежести: устаревшая сверка скрывала бы аварию https-порта у хостов с URL `http://`)
- KTD3. **Обе сверки стоят в выражении «Нет соединения TCP», а не в зависимостях:** `max(tcp,#2)=0 and (last(порт)={$WEB_SERVICE.HTTPS.PORT} or nodata(порт,15m)=1) and (last(хост)="{$WEB_SERVICE.HOST}" or nodata(хост,15m)=1)`. Зависимость не закрывает проблему, открытую раньше главного триггера, и замораживает зависимый триггер, пока главный открыт. В выражении свежая сверка с расхождением закрывает и уже открытый AVERAGE, а без свежих данных сертификата условие истинно, и TCP-авария работает как до 2.6.0. «Медленное соединение TCP» и TLS scan timeout по-прежнему зависят от «Нет соединения TCP» с новым выражением. Заменяет зависимость из 2.6.0 (R14 того плана). (session-settled: user-directed — chosen over зависимостей: ложный AVERAGE, открытый до сверки, оставался бы до ручного закрытия)
- KTD4. **«Нет данных TCP-проверки» — `nodata(.../net.tcp.service.perf[https,…],15m)=1 and nodata(.../web.test.fail[Web service],{$WEB_SERVICE.NODATA.PERIOD})=0` на https-элементе, AVERAGE, `scope: data-collection`, без зависимостей.** Условие на веб-сценарий стоит в выражении, как в триггере сертификата с 2.5.1. Зависимость замораживала бы триггер, пока открыт главный, а пересчёт после его закрытия ждёт нового значения элемента, которого у NOTSUPPORTED-элемента нет. Выражение с `nodata()` пересчитывается по таймеру каждые 30 с. 15m — три интервала `{$WEB_SERVICE.DIAG.CHECK.INTERVAL}` по умолчанию, как у нет-данных сертификата. Отдельный макрос периода не вводится: остальные нет-данных шаблона, кроме веб-сценария, тоже с литералом.
- KTD5. **На хосте, где TCP-элементы отключены вручную, «нет данных» не срабатывает.** Триггеры на отключённых элементах не вычисляются. Специальной обработки не нужно.

### Assumptions

- Объём плана принят без отдельного подтверждения (запуск `confirm:auto`): сверка имени, «нет данных» TCP, описания и README. Если что-то из этого не нужно, план правится до U1.
- Важность WARNING для сверки имени взята по образцу сверки порта; AVERAGE для «нет данных» — по образцу остальных триггеров нет-данных шаблона.

## Implementation Units

### U1. Сверка имени хоста

- **Goal:** WARNING при несовпадении `{$WEB_SERVICE.HOST}` с хостом URL и подавление TCP-аварии при нём.
- **Requirements:** R1, R2; AE1, AE2, AE5; KTD1–KTD3.
- **Dependencies:** нет.
- **Files:** `templates/web-service-by-itforprof/template_web_service_by_itforprof_com.yaml`, `templates/web-service-by-itforprof/i18n/ru.yaml`, `templates/web-service-by-itforprof/template_web_service_by_itforprof_com_ru.yaml` (генерируется), `scripts/tests/test_template_contract.py`, `scripts/tests/test_cert.py`.
- **Approach:**
  1. Элемент `web_check.cert.host` рядом с `web_check.cert.port`, по KTD1, тег `scope: diag`.
  2. Триггер WARNING по KTD2 с `manual_close`, тегами `scope: diag` и `url`, `event_name` с хостом из проверки (`{ITEM.LASTVALUE1}`) и `{$WEB_SERVICE.HOST}`, описанием, что задать на хосте.
  3. Условие обеих сверок в выражении «Нет соединения TCP» вместо зависимостей (KTD3); выражения зависимостей «Медленное соединение TCP» и TLS scan timeout обновить.
  4. Переводы новых строк в `i18n/ru.yaml` и пересборка `_ru.yaml`, чтобы `pytest -q` был зелёным на коммите юнита.
- **Patterns to follow:** элемент и триггер `web_check.cert.port` и тесты к ним в `scripts/tests/test_template_contract.py`; сквозной тест `test_cert_reports_the_url_port_the_template_compares` в `scripts/tests/test_cert.py`.
- **Test scenarios:**
  - Covers AE1. Выражение сверки равно строковому сравнению `last(...web_check.cert.host)` с `"{$WEB_SERVICE.HOST}"`, WARNING, `manual_close`, теги `scope: diag` и `url`, `event_name` содержит `{$WEB_SERVICE.HOST}`; без `nodata(` и без зависимостей.
  - Предобработка элемента: `NOT_MATCHES_REGEX "ok":false` с `DISCARD_VALUE`, затем JSONPath `$.host`; история 7d; нет `DISCARD_UNCHANGED_HEARTBEAT`.
  - `test_cert_dependents_discard_the_error_envelope`: зависимых элементов сертификата 19 в полном профиле и 17 в Certificate-TLS.
  - Covers AE2. Выражение «Нет соединения TCP» содержит обе сверки с условием свежести, зависимостей нет; `test_trigger_dependency_expressions_match_target_triggers` проходит.
  - Covers AE5. Сквозной тест в `test_cert.py`: `check_cert` на локальном TLS-сервере отдаёт `host` в нижнем регистре, а JSONPath элемента его находит; `url_host` для `http://Example.org/` даёт `example.org`, а для `https://xn--80aac7bmkkfg.xn--p1ai/` возвращает хост в форме `xn--` без изменений.
- **Verification:** контрактные тесты зелёные; граф зависимостей без циклов.

### U2. Нет данных TCP-проверки

- **Goal:** AVERAGE, когда https-проверка TCP молчит 15 минут.
- **Requirements:** R3; AE3, AE4; KTD4, KTD5. Реализует Key Decision «При сбое сборщика задача одна» (session-settled: user-directed), которому подчинён R3.
- **Dependencies:** нет.
- **Files:** `templates/web-service-by-itforprof/template_web_service_by_itforprof_com.yaml`, `templates/web-service-by-itforprof/i18n/ru.yaml`, `templates/web-service-by-itforprof/template_web_service_by_itforprof_com_ru.yaml` (генерируется), `scripts/tests/test_template_contract.py`.
- **Approach:** переводы и пересборка `_ru.yaml`, как в U1; триггер на https-элементе TCP по KTD4, `manual_close`, теги `scope: data-collection` и `url`, `event_name` и описание с перечнем причин (адрес не задан, порт нечисловой или с пробелом, сборщик не опрашивает).
- **Patterns to follow:** «Cert externalscript no data received» (выражение `nodata`, AVERAGE, `scope: data-collection`, описание с причинами).
