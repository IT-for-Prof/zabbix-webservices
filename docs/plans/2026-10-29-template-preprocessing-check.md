# Проверка preprocessing шаблонов после импорта

## Повод

При деплое 7.0-2.5.0 импорт вставил первым шагом фильтр конверта ошибки в
элементы сертификата. Zabbix 7.0.32 обновляет шаги preprocessing по номеру и
оставляет в шаге поля, которых нет в новом определении. Проверено на
временном шаблоне:

| Действие | Результат |
|---|---|
| Импорт, в котором шаг вставлен первым | новый `DISCARD_VALUE` получает `error_handler_params` старого первого шага; `BOOL_TO_DECIMAL` получает `params: 1h` |
| То же, в YAML явно `error_handler_params: ''` | мусор остаётся |
| `item.update` без поля `error_handler_params` | мусор остаётся, ответ — успех |
| `item.update` со всеми полями, пустые как `""` | чисто |
| повторный импорт того же файла поверх чистого элемента | остаётся чисто |
| сохранить элемент с мусором (так делает форма интерфейса) | отказ `error_handler_params: value must be empty` |

Экспорт эти поля не печатает, поэтому сверка «файл против экспорта» даёт
0 расхождений. Сбор данных мусор не ломает: у двух элементов http3 он
лежал с 2.3.3 на 44 хостах, значения писались нормально. Ломается правка
элемента в интерфейсе.

Сейчас шаблоны проекта на обоих серверах чистые: их исправили вручную
одноразовым скриптом. Шаг «сверить через API» записан только в плане
2026-10-29, и при следующем деплое его легко пропустить.

## Цель

После любого импорта шаблона одной командой узнать, совпадает ли
preprocessing в базе с файлом, и при расхождении исправить его.

## U1 — Скрипт `scripts/check-template-preprocessing.py`

- [x] Аргументы: один или несколько YAML-файлов шаблонов; по умолчанию два
  английских файла проекта. Тексты ошибок в preprocessing не переводятся,
  поэтому английский и русский файлы дают одинаковые шаги.
- [x] Шаблон на сервере ищется по техническому имени из файла
  (`template`). Ненайденный шаблон — сообщение и пропуск (на myzabbix нет
  Certificate-TLS), но если не найден ни один шаблон из аргументов, код
  выхода 1.
- [x] Перед сравнением сверить `vendor_version` шаблона на сервере
  (`template.get`) с `vendor.version` в файле. При расхождении вывести обе
  версии, шаблон не сравнивать и не записывать, код выхода 1. Иначе запуск
  из другой ветки примет настоящие изменения версии за мусор импорта, а
  `--apply` запишет на сервер чужой preprocessing.
- [x] В начале отчёта: сервер (`ZABBIX_URL`) и найденные шаблоны с
  версиями.
- [x] Охват: элементы, правила LLD и прототипы элементов шаблона.
  Хосты получают preprocessing по наследованию, их не трогаем.
- [x] Сравнение по ключу элемента: тип шага, `params` (строки
  `parameters` через `\n`), `error_handler`, `error_handler_params`.
  Названия из YAML (`JSONPATH`, `DISCARD_VALUE`) переводятся в коды API
  таблицей в скрипте.
- [x] Объект из файла, которого нет на сервере, — расхождение (импорт не
  прошёл). Объект, который есть только на сервере, выводится отдельным
  списком и ошибкой не считается: импорт не удаляет лишнее.
- [x] По умолчанию только отчёт: шаблон, ключ, номер шага, что ожидается
  и что лежит в базе. Код выхода 1, если есть расхождения.
- [x] `--apply`: `item.update` / `discoveryrule.update` /
  `itemprototype.update` с полным списком шагов, где все четыре поля
  переданы явно, пустые как `""`. Результат проверяется повторным
  запуском без флагов.
- [x] Подключение как у `sync-domain-registry-owners.py`: `ZABBIX_URL`,
  `ZABBIX_TOKEN` из окружения или `scripts/.env` через `_zabbix_client`.
  Второй сервер — второй запуск с другим окружением.

## U2 — Тест `scripts/tests/test_check_template_preprocessing.py`

- [x] Ожидаемые шаги из YAML: `BOOL_TO_DECIMAL` с `parameters: ['']` даёт
  пустые `params`, обработчик по умолчанию — `0`.
- [x] Шаг из базы с лишним `error_handler_params` или `params` у
  `BOOL_TO_DECIMAL` считается расхождением; совпадающий — нет.
- [x] `--apply` на поддельном клиенте: каждый шаг в вызове `*.update`
  содержит все четыре поля; при несовпадении версий шаблона нет ни одного
  вызова `*.update`.
- [x] Объект из файла, отсутствующий на сервере, даёт расхождение; лишний
  объект на сервере — нет; ни одного найденного шаблона — код выхода 1.
- [x] Каждый элемент обоих файлов проекта переводится без неизвестных
  типов шагов и обработчиков.

## Проверка

- [x] pytest, `ruff check`, `ruff format --check`.
- [x] Запуск без `--apply` на обоих серверах: 0 расхождений (шаблоны уже
  чистые).
- [x] Воспроизвести мусор на временном шаблоне и убедиться, что скрипт его
  находит, а `--apply` убирает. Временный шаблон пишется отдельно, со своим
  именем и своими UUID шаблона и элементов — не копия файла проекта: при тех
  же UUID импорт перепишет боевой шаблон, а удаление снимет его со всех
  хостов. К шаблону привязать один выключенный хост и после `--apply`
  сверить через `item.get` все четыре поля шагов его элемента. Перед
  удалением проверить шаблон по `templateid`; хост удалить вместе с ним.

## Вне объёма

- Чистка сторонних шаблонов на серверах: там тот же эффект, но шаблоны не
  наши.
- Элементы, заданные прямо на хостах, а не в шаблонах.
- Сообщение об ошибке в трекер Zabbix.
