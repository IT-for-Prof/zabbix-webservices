# Исправление эскалации сбоя сертификата и документации severity

## Согласованный объём

Первоначально план включал исправление README и диагностику длительного
Cert check failing. После ревью пользователь поручил исправить проблему
и проверить результат на mon.itforprof.com. Этот запуск включает новую
эскалацию в обоих профилях и её развёртывание на этом сервере.

## Принятые решения

- Сохранить текущие severity, пороги и условия триггеров (session-settled: user-approved).
- Сохранить различия между полным профилем и Certificate-TLS, включая сроки
  предупреждения и severity истёкшего сертификата (session-settled: user-approved).
- Не менять HTTP/3, WHOIS и правила Planfix в рамках этой работы
  (session-settled: user-approved).

Существующие триггеры сохранены. Новое поручение пользователя разрешает
добавить отдельный AVERAGE для длительного сбоя и необходимые проверки.

## U2 — Устранить длительный сбой проверки сертификата

Причина: ошибка DNS/TCP/TLS возвращается как валидный JSON ok=false
с кодом выхода 0 (scripts/externalscripts/web_check.py, check_cert →
cmd_cert → emit). Master item продолжает получать данные,
web_check.cert.ok становится 0, а существующий триггер имеет INFO.
Nodata проверяет поступление данных, поэтому этот путь не повышал severity.
Три офлайн-вызова CLI с подменённым сбоем DNS подтвердили путь ошибки.

- [x] Сохранить мгновенный INFO: на него завязано подавление ложных
  тревог по метаданным сертификата.
- [x] В каждом профиле добавить Cert check failing on 3 consecutive checks
  с AVERAGE: count(cert.ok,#3,"eq",0)=3 и свежий master item.
- [x] Убрать отбрасывание неизменившихся значений только у cert.ok,
  чтобы три значения соответствовали трём запускам проверки.
- [x] Проверять свежесть через nodata(master, period)=0 в выражении,
  без зависимости от no-data: активная зависимость может задержать закрытие
  уже открытой проблемы. При отсутствии данных AVERAGE длительного сбоя
  закрывается и остаётся отдельный no-data сигнал.
- [x] Обновить каталог перевода и сгенерировать обе русские версии.
- [x] Расширить существующие тесты контракта обоих профилей.
